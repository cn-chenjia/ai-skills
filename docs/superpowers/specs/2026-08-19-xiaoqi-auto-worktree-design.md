# 小七按需自动准备工作区设计

## 背景

小七支持一个项目同时跟踪多个需求，每个需求拥有独立账本。当前
`sprint-manage/local/session.yaml` 只记录一个当前需求；如果多个开发会话在同一
工作目录内并行，它们会相互覆盖当前需求指向，也可能在同一目录修改不同需求。

本次调整不要求需求创建时立即建立新工作区。需求可以先完成调查、方案和任务确认，
只有准备进入编码时才处理工作区隔离。

## 目标

- 第一个进入编码的需求可以继续使用当前工作区。
- 第二个并行进入编码的需求自动获得独立分支和工作区。
- 新工作区从需求账本记录的基线分支创建，不继承其他需求分支上的提交。
- 每个工作区拥有自己的本地当前需求记录。
- 重复执行准备动作不会重复创建分支或工作区。
- 无法安全判断时停止，不猜测、不覆盖现有目录和分支。

## 非目标

- 不支持多个编码会话在同一工作目录内并行修改。
- 不在需求调查或方案阶段提前创建工作区。
- 不替代 Git、宿主沙箱或用户权限控制。
- 不自动删除、移动或合并已有工作区。

## 方案

新增独立的“准备工作区”步骤，在 `apply` 开始前、交付状态从
`not-started` 推进到 `coding` 之前执行。该步骤与状态推进工具分离，避免 Git
操作失败时误改交付状态。

流程如下：

```text
需求准备进入编码
  -> 读取并校验全部需求账本
  -> 确定基线分支
  -> 判断当前工作区能否分配给该需求
  -> 可用：绑定当前工作区
  -> 已被其他编码需求占用：创建独立分支和 worktree
  -> 写入目标工作区的 local/session.yaml
  -> 返回目标工作区
  -> 小七在目标工作区继续 apply
```

## 基线分支

需求账本在 `协作` 下增加可选字段：

```yaml
协作:
  基线分支: "main"
```

旧 V4 账本继续有效。需求尚未编码时字段可以为空；准备工作区时按以下顺序确定：

1. 使用账本中已明确的基线分支。
2. 使用远端默认分支。
3. 使用本地 `main` 或 `master`，前提是只有一个候选。
4. 仍无法唯一确定时停止并请求用户确认。

确定后将基线分支写入需求账本。进入 `coding` 前必须有明确的基线分支、需求分支和
工作区。

## 当前工作区分配

项目根工作区本身可以分配给第一个编码需求，不需要额外创建 worktree。分配前必须
确认：

- 没有其他 `active` 且处于编码或后续交付状态的需求占用该工作区。
- 当前分支与需求分支一致，或可以从基线分支安全创建需求分支。
- 当前未提交改动不会被切换分支覆盖。
- 需求之间不存在分支、工作区、冲突键或影响范围冲突。

只要任一条件无法确认，就不在根工作区切换分支，而是尝试创建独立 worktree；如果
独立 worktree 也无法安全创建，则停止并报告原因。

## 自动创建

默认命名：

```text
需求分支：沿用账本已声明值；缺失时使用 codex/<需求编号>
工作区：.worktrees/<需求编号>
```

创建动作等价于从基线分支建立需求分支，再为该分支建立 worktree。`.worktrees/`
必须被 Git 忽略；如项目尚未忽略，小七在创建前加入项目 `.gitignore`。

创建后更新需求账本中的基线分支、需求分支和工作区，并在新工作区创建：

```text
sprint-manage/local/session.yaml
```

该文件只记录当前用户和当前需求，继续保持不提交 Git。

## 重复执行与已有资源

准备步骤必须可重复执行：

- 账本分支和 worktree 已正确关联：直接复用。
- 分支存在但尚未绑定其他 worktree：核对基线关系后复用。
- 目标目录存在且确认为同一需求的 worktree：直接复用。
- 分支、目录或 worktree 归属不一致：停止并报告冲突。
- 部分创建失败：不推进交付状态；保留可识别资源，下一次执行重新核对后恢复。

准备步骤禁止自动删除可疑目录、强制重置分支或覆盖未提交改动。

## 状态与账本更新

准备步骤只更新工作区相关信息，不负责把交付状态推进到 `coding`。更新需求账本时
仍使用账本锁并递增 revision。

成功结果包含：

- `outcome: completed`
- 需求账本路径
- 基线分支
- 需求分支
- 目标工作区
- 是新建、复用还是绑定当前工作区
- 推荐下一动作 `apply`

失败结果包含：

- `outcome: blocked | needs_confirmation | failed`
- 未完成原因
- 已创建但未绑定的资源
- 恢复条件

## 小七路由调整

小七在以下条件同时满足时调用准备步骤：

- 用户已确认需求并准备执行 `apply`。
- 需求交付状态为 `not-started`。

准备成功后，小七把后续命令的工作目录切换到返回的目标工作区，再执行 `apply`。
准备失败时不开始编码、不推进交付状态。

已经处于 `coding` 或后续状态的需求只校验账本所指工作区，不重新创建。

## 测试

至少覆盖：

- 单一需求绑定当前根工作区。
- 第二个并行需求从基线分支创建独立 worktree。
- 账本明确基线分支和自动发现默认分支。
- 无法唯一确定基线分支时停止。
- 重复准备同一需求时复用已有资源。
- 分支已存在、目录已存在和 worktree 归属冲突。
- 未提交改动存在时不进行危险切换。
- 创建失败时不推进交付状态。
- 新工作区生成独立 `local/session.yaml`。
- 旧 V4 账本未填写基线分支时仍可读取和迁移。
