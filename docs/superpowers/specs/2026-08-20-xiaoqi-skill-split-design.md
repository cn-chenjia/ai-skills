# 小七主技能精简设计

## 背景

`sprint-manage-xiaoqi/SKILL.md` 当前同时承载会话锁、流程路由、账本协议、连续执行、并行协作、收尾门禁和宿主接入说明。主文件内容过重，既增加每次加载成本，也让同一规则在主文件和参考文件中重复维护。

本次调整采用“主技能始终掌权，参考文件按需加载”的结构。拆出的参考文件只提供当前动作所需规则，不获得独立入口、会话控制权或流程结束权。

## 目标

- 将主技能收敛为会话锁和流程路由入口。
- 保持现有触发方式、用户操作、账本格式和脚本行为不变。
- 让模型只在需要时读取账本、执行、协作、收尾或运行时细节。
- 消除主文件与参考文件重复保存同一规则的问题。
- 保证任何参考流程完成后都返回主技能，由主技能读取真实状态并决定下一步。

## 非目标

- 不修改 V4 账本结构和状态迁移。
- 不修改 OpenSpec、Superpowers 或项目工具的职责。
- 不新增可由用户独立触发的小七子技能。
- 不调整脚本功能、Hook 协议或宿主权限边界。
- 不改变 `ready`、`blocked`、`closed` 等停止条件。

## 总体结构

### 主技能

`SKILL.md` 只保留以下职责：

1. 会话锁、续接消息和 `退出小七` 规则。
2. 触发边界、流程所有权和内部能力边界。
3. 启动时识别项目、需求和真实状态所需的最小检查。
4. 根据用户意图和当前状态选择一份必要参考文件。
5. 接收下游结果，重新读取真实状态并继续路由。
6. 在 `ready`、`blocked`、`closed` 或明确人工门禁处停止。

主技能不再展开账本字段、并行冲突判定、完整实施循环、收尾步骤、Hook 安装命令等细节。

### 参考文件

| 文件 | 唯一职责 |
| --- | --- |
| `references/state-contract.md` | 账本创建、状态、证据、锁、版本和迁移 |
| `references/step-details.md` | OpenSpec 动作选择、连续执行、验证和失败恢复 |
| `references/collaboration.md` | 多需求、多人协作、分支、工作区和写入范围冲突 |
| `references/closing.md` | `ready` 后的选择、同步、归档、分支收尾和关闭 |
| `references/runtime-contract.md` | Hook、Codex、Trae、安装、体检和宿主边界 |
| `references/event-contract.md` | 通用事件协议和适配器数据约定 |

现有内容优先移动和去重，不复制出新的同义规则。`state-contract.md` 与 `step-details.md` 保留原有文件名，避免无意义的引用变更。

每份参考文件开头统一声明：

> 本文件只提供当前动作的操作规则，不拥有会话或流程控制权。完成或中断后必须返回 `SKILL.md`，由主技能重新读取真实状态并路由。

## 路由规则

| 当前意图或状态 | 读取的参考文件 |
| --- | --- |
| 新建、恢复、查看需求；处理账本或状态 | `state-contract.md` |
| 开始、继续、更新、验证；处理普通失败 | `step-details.md` |
| 多需求、多人协作、分支或工作区冲突 | `collaboration.md` |
| 已到 `ready`；请求归档、PR、合并、保留或关闭 | `closing.md` |
| 安装、Hook、Codex、Trae、体检或宿主异常 | `runtime-contract.md` |
| 处理规范化底层事件或适配器数据 | `event-contract.md` |

一次判断只加载当前动作需要的参考文件。若动作过程中出现新的独立问题，先返回主技能，再由主技能决定是否读取另一份参考文件，避免参考文件之间形成平行流程。

## 执行闭环

```text
主技能识别会话与意图
  -> 读取原生状态
  -> 选择必要参考文件
  -> 执行动作并收集 outcome/evidence/blockers
  -> 返回主技能
  -> 再次读取真实状态
  -> 继续路由或在合法停止点结束
```

下游结果继续使用统一结构：

- `outcome`
- `summary`
- `evidence`
- `blockers`
- `recommended_next`

参考文件可以建议下一动作，但不能自行宣告需求完成、解除会话锁或把控制权交给另一套流程。

## 失败与人工门禁

- 账本和状态错误由 `state-contract.md` 处理。
- 实施、测试、构建、评审和 OpenSpec 检查失败由 `step-details.md` 处理。
- 并行冲突和工作区占用由 `collaboration.md` 处理。
- 归档和分支收尾失败由 `closing.md` 处理。
- Hook、宿主或运行时问题由 `runtime-contract.md` 处理。

对应参考文件完成恢复尝试后，必须将结果交还主技能。只有需要业务决定、权限授权、破坏性操作确认、连续修复失败或无法可靠判断事实时，主技能才进入人工门禁或 `blocked`。

## 内容迁移

### 保留在主技能

- 会话锁约束和续接消息优先级。
- 小七定位、触发边界、流程所有权和职责边界。
- 原生动作的简明路由表。
- 最小启动检查。
- 参考文件选择表。
- 返回主技能的统一闭环。
- 精简的交互输出和停止条件。

### 移出主技能

- 账本字段、状态证据和锁操作细节移至 `state-contract.md`。
- 模型连续执行、自动修复和动作细节移至 `step-details.md`。
- 单写者、需求隔离和多人共享 change 移至 `collaboration.md`。
- 验证后收尾、最终状态和关闭条件移至 `closing.md`。
- Harness、Codex、Trae、Hook、安装和体检移至 `runtime-contract.md`。
- 底层事件和适配器说明继续由 `event-contract.md` 承担。

## 测试与验收

### 行为不变量

- 明确提到“小七”后，会话锁仍然生效。
- “确认、可以、执行、继续”等短消息仍沿用当前小七流程。
- 只有 `退出小七` 或既有合法停止条件能解除或暂停流程。
- 主技能始终拥有路由和最终判断权。
- 没有已确认账本时不能进入实施、验证、归档或收尾。
- `ready` 后仍需用户选择收尾方式。
- 交付状态只能通过现有脚本和真实证据推进。

### 测试调整

- 将依赖主文件大段文字的测试改为验证职责、路由入口和行为不变量。
- 增加检查，确保每份参考文件包含“返回主技能”的控制权声明。
- 增加检查，确保主技能能路由到所有参考文件。
- 保留现有账本、工作区、状态推进、Hook 和运行时测试。
- 运行全部 Node 测试和技能格式校验。

### 完成标准

- 主技能明显缩短，目标约 150 至 200 行；若保留必要约束需要略微超出，以行为完整为先。
- 主技能不再重复参考文件中的操作细节。
- 每类意图都有唯一且可发现的参考入口。
- 所有原有测试和新增结构测试通过。
- 对外说明与新结构一致，不再引导读者把主技能当作完整操作手册。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 拆分后遗漏关键规则 | 先建立行为不变量测试，再迁移文字 |
| 参考文件获得平行控制权 | 每份参考文件声明控制边界，主技能规定统一返回闭环 |
| 同一规则继续多处维护 | 每条细节规则只保留一个权威文件，主技能只写路由摘要 |
| 测试只检查文字而非行为 | 将主文件正则测试改为职责和结构测试，并保留脚本行为测试 |
| 一次加载多个参考文件导致上下文再次膨胀 | 主技能规定一次只加载当前动作所需参考文件 |
